### Step 3 – Understand MCP UI embedding

From MCP UI docs, the core you must grasp:

* You embed their UI as an **iframe**
* You talk via `window.postMessage`:

  * MCP UI → host (Chat UI)
  * Host → MCP UI
* You must handle events like:

  * `intent`
  * `tool`
  * `prompt`
  * `notify`
  * `link`
  * `data` requests
  * `size` updates

In practice, you’ll probably create something like:

```tsx
// Pseudo-code
<McpUiWrapper resource={uiResource} onAction={handleUiAction} />
```

That component:

* Creates an iframe
* Initializes MCP UI client
* Hooks postMessage events to your handler
* Forwards actions through Archestra’s existing MCP / LLM gateways

### Step 4 – MCP Gateway + LLM Gateway

The bounty explicitly says:

> Make sure it works in 3rd-party UI via MCP Gateway
> Make sure it works in 3rd-party UI via LLM Gateway

This means:

* Not just Archestra’s own Chat UI
* But **other UIs** using:

  * MCP Gateway → MCP server
  * LLM Gateway → LLM + MCP combo

You need to ensure:

1. **Gateway does not break UIResource**:

   * No stripping `_meta`, `uiMetadata`, `blob`, etc.
   * JSON-RPC payloads must pass through unchanged.

2. **Actions from the third-party UI**:

   * When user interacts (clicks buttons in MCP UI iframe),
   * Requests go → gateway → MCP/LLM → back → UI

You’re basically making sure the gateways treat UIResources like first-class citizens instead of “just text”.
